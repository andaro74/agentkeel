### Close detail (PR 4, #10, the close, 2026-09-22)

**Row 1 is RED.** The cap was four and four were used. The first half of
the claim was measured and held; the second half was never read.

**The measurement.** The Measured cell is copied from the gate's reading of
the envelope for `e97125e970ccfc6d044612eb006cdbdbcdb99337`, written by the
`record` job of CI run 35680056132 as `github-actions[bot]` (`ad7f161`).
That envelope is the last measurement of the tree PR 3 merged (`616b620`),
and the first to record where refagent ran. It says `mode: runner`, and its
own verdict is GREEN. As row 1 reads it, the verdict is **UNMEASURED**:
M01 is in `READ_IN_THE_RUNTIME`, and an envelope that did not run in the
runtime has not read "refagent runs inside the construct" (PR 3 cold review
B1). SPEC/00 §7 makes a close without a measurement RED. `src/ledger.py` did
not yet apply that to an UNMEASURED reading, and this PR makes it do so
(ruled by the human for Product and Engineering, 2026-09-22). `make ledger`
exits 0 with State RED beside that cell, and would exit 1 on GREEN.

What the envelope says, as numbers: agent traps 3/3, ordinary 9/9,
guardrail 0/3; control traps 1/3, ordinary 0/9, guardrail 0/3;
`never_passed` 3 (the three guardrail goldens, which wait for M03's
guardrail); `regressed` 0; plants 0/0; `F0_2`, `F0_3`, `F1_1` to `F1_4` all
pass; 54,156 tokens against a cap of 150,000.

**This PR measures again, and the row does not move**, as at M00's close.
`src/ledger.py` is not prose to `evals.yml`'s "already measured" step, so
this PR's run spends tokens and writes its own envelope. Row 1 stays on
`e97125e` by ruling: adding the SPEC/00 §7 rule to the ledger does not
reopen the claim. This PR's run is recorded in `rulings/pr4.md` with its
id. If a check fails in it, this PR is RED and the row is rewritten before
the tag.

**Why the second half was never read.** The merge of PR 3 was the first
real deploy, and it failed twice (run 35683865472):
1. `AWS_DEPLOY_ROLE_ARN` had never been set as a repository variable.
   `infra/bootstrap/README.md` step 3 sets only the eval role's. The human
   set it, and the job was re-run.
2. The rights table failed to create. `TableEncryption.AWS_MANAGED` makes
   CloudFormation call `kms:CreateGrant` on the `aws/dynamodb` key, and
   `agentkeel-deploy-boundary` denies that call on every key (R4). R4 held,
   and nothing was half-built: the stack rolled back to
   `ROLLBACK_COMPLETE`, the human deleted it, and the image stays in ECR.
   The cause is ours. PR 3 took cfn-exec's action lists from AWS's handler
   permissions, but dropped `kms:CreateGrant` as a call made "only for a
   customer key". The simulated read-back could not catch it: the refusal
   came from a deny that is meant to be there.

The fix is one line, `TableEncryption.DEFAULT`. A fifth PR is a RED close
with the finding as its result, so the fix is `milestones/M02/open.md` row
9, M02 PR 1. A later successful deploy does not reopen row 1.
