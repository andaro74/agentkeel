# M05 — The agent stays in its box

## In one sentence

An agent is stopped from reaching the internet, writing to another
agent's files, or deleting its own logs, and each attempt is recorded in
a separate account it cannot change.

## Why it matters

An agent runs code, calls tools and reads what they return. A tool can
leak a password into its answer. A crafted question can talk the agent
into calling somewhere it should not. A compromised agent can try to
reach the internet, write into another team's files, or wipe its logs
so nobody sees what it did. And someone with admin rights where the
agent runs can edit the evidence afterwards.

M05 is about two things at once. Each of these attempts must be refused
by a control built for it. And each must leave a record in a second
cloud account, one that nobody in the agent's account can change or
delete, within ten minutes. A refusal nobody can prove afterwards is
half a control.

One person holds every owner's seat on this project, and creates the
second account. The platform records who ruled on each control. It does
not record that a second person looked.

## What we planted

We wrote seven ways for the claim to be false and put them in the
repository before any code that could catch them.

Five are the attempts. A download from the internet, from where the
agent runs. A write into another agent's folder of files. Deleting the
agent's own log. A request that arrives after passing through two other
agents first, one hop more than the agent is allowed. And a tool answer
that carries a password, which the agent repeats. Today the first three
should be refused by what is already there, though no one has tried
them yet, and any record of them would stay in the agent's own account,
where an admin can delete it. The control that keeps an agent out of
another agent's folder does not exist yet: today there are no folders. The last two are not refused at
all: the agent answers the too-deep request, and the answer with the
password passes every test.

The sixth is an attempt, from the agent's account, to delete or unlock
a stored record of evidence. Today there is no locked store: the
evidence lives in the project's history.

The seventh is an emergency stop for a misbehaving agent, tried and then
checked: can the agent still call its model? Today there is no stop.

## For the business user

What M05 is meant to show: an agent built on this platform cannot reach
the internet, write where another agent keeps its files, or delete its
own logs, and every try is on record in a separate account within ten
minutes. Security owns the controls and the second account; the
threshold owner owns the ten minutes.

Not measured at M05, stated now. The attempts are made by the platform
owner acting as the agent, not by a hostile agent; that is M08's
rehearsal. A caller can still lie about how many agents a request passed
through until agent identity arrives at M07. That the too-deep request
was refused rests on the agent's own record and on its model not being
called. A password in a live tool answer is not tried until M06. Records
are kept one day during M05, not the seven years the platform promises;
seven years is measured at M08. An admin in the agent's account can still stop
the recording going forward, though not erase what was already sent.
