# M02 — Rules have owners

## In one sentence

A rule, a test, or a threshold changes only when the person who owns it
says so, and loosening one needs two owners.

## Why it matters

The quickest way to make a red build green is not to fix the agent. It
is to raise the bar it failed, soften the test it failed, or delete the
test. Each of those is one line in one file, and each looks like
housekeeping in a code review. M02 gives every file in the platform an
owner, and makes the platform refuse a change to an owned file unless a
written ruling from that owner comes with it. Loosening anything takes
two owners. And the person who runs the repository cannot push past a red
check either: the repository is set so that nobody can, and the platform
checks that setting every time.

One thing to say plainly before the rest. On this project one person
holds every owner's seat. "Two owners" here means two written rulings
from two seats, and one person can write both. What the platform holds
is that the change is named, under the seat that owns the file, in a
file that stays with the history. It does not hold that somebody else
agreed. That is the design for a proof of concept with one engineer; a
team would put a person in each seat.

## What we planted

We wrote five changes that must never reach the main branch, and put
each one in the repository as a patch a test can apply.

The first raises the spending limit on a test run from 150,000 tokens to
300,000, with a ruling from the one owner who sets that limit and nobody
else. One owner is not enough to loosen a limit. A second version of it
comes with two rulings, both from the same owner; two pieces of paper
from one seat are still one key.

The second edits a trick question so that the wrong answer now counts as
right: the question was written to catch an agent that ignores a
holdback date, and the edit tells the grader to reward exactly that.

The third has the reference agent declare that it may call a second
agent, while the second agent says nothing about being called. Every
connection between agents must be declared on both ends.

The fourth is not a file but an attempt. After the checks are in place,
the owner of the repository will try to merge a change whose check is
red, using the administrator's override; and then will try to give
themselves permission to override, and see whether the platform notices.

The fifth renames a test question's id, keeping its content. A question
is retired, never renamed: renaming one erases its history.

## For the business user

What M02 has to show, and has not shown yet: when a team runs an agent on
this platform, the tests it must pass, the limits it must stay under and
the rules it must follow each have a named owner, and none of them can be
changed on the quiet. A change comes with a ruling from its owner, kept
with the history. Loosening a test or a limit needs two. The team decides
what the agent says; the owners decide what counts as passing; nobody,
including the person who runs the repository, can merge past a red check.
Until each check has refused its planted case, this paragraph is the
goal, not the result.

One limit, stated now. At this milestone one person holds every seat, so
"two owners" is two rulings that one person can write. The platform
proves the change was named and by whom; it does not prove a second
person looked.
